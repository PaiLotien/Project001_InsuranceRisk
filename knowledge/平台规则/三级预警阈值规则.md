# 三级预警阈值规则（黄 / 橙 / 红）

更新：2026-11-11（upgrade/v2）。规则文件：config/alert_rules.yaml；判级代码：src/alerts/thresholds.py；阈值持久化：src/config/threshold_store.py。

## 预期成本率三条判级规则
预警等级只由预期成本率决定，预期成本率 = 预期赔付率 + 成本率1。三条规则：
- R005 黄色：预期成本率超过 90%（严格大于 90%）。来源：预警规则配置表.xlsx R005。
- R011 橙色：预期成本率超过 95%（严格大于 95%）。95% 是默认参考值，状态为“待业务确认”。
- R010 红色：预期成本率超过 100%（严格大于 100%），通用盈亏线。R010 是系统原有经验阈值，状态为“待业务确认”，不属于配置表明确给出的四条规则。
默认阈值：黄 90%、橙 95%、红 100%。

## 最高等级优先与边界取值
判级顺序为“红 > 橙 > 黄”，命中更高等级就不再看低等级。所有比较都是严格大于（gt），等于阈值不触发该级：
- 预期成本率恰好等于 100% 判为橙色，不是红色（红色要求严格大于 100%）。
- 恰好等于 95% 判为黄色；恰好等于 90% 不预警（正常）。
- 例如 100.1% 判红色，96% 判橙色，92% 判黄色，88% 正常。
红色是否改为“大于等于 100%”需业务确认，系统目前保持严格大于。

## 橙色为什么曾经不触发
旧版本橙色阈值默认 100%，与红色相同；判级时橙色要求“橙色阈值 < 红色阈值”，两者相等时橙色永远不触发。11.1 修复后新增 R011，橙色默认 95%，橙色可以正常触发。

## 页面修改阈值与持久化
侧栏可修改黄 / 橙 / 红三级阈值，保存时校验 0 ≤ 黄 < 橙 < 红，不满足会报错“阈值须满足黄色＜橙色＜红色”。用户阈值保存在本机 SQLite 数据库 data/runtime/irds.db 的 user_thresholds 表，刷新页面不会丢失；可一键恢复默认（删除用户阈值，回到 YAML 默认 90/95/100）。AI 顾问不能修改阈值，改阈值须走规则配置流程并由业务负责人确认。

## 阈值矩阵（机构 × 车型）
config/threshold_matrix.yaml 支持按“机构 × 车型 × 规则编号”精确覆盖阈值，例如某机构家用车 R005 设为 92。未配置时使用全局阈值。当前矩阵为空。

## R008 出险频度规则与前置条件（任一满足）
R008：出险频度月同比上升超过 1 个百分点，触发黄色预警。前置条件逻辑为 any（“或”），两个条件满足任意一个即可评估：
- 当月满期保费 > 100 万元；
- 当月满期进度 > 2 个月。
11.1 反馈前是“且”（两个都要满足），已改为“或”（precondition_logic: any）。出险频度是比例型指标，变化用“百分点”表达。等级与推送对象仍待确认。

## 其他已启用规则
- R006 黄色：单均保费月环比下降超过 10%。
- R007 黄色：案均赔款月同比上升超过 20%。
- R009（自主系数均值商业）阈值未确认，未启用，不得自行推断。
- 组合规则 C001：同一机构、车型、期间同时命中 R008 与 R007 时升一级，最高到红色。

## 合计行不定级
机构、车型或序号以“合计 / 小计 / 总计”结尾（忽略空白，如“合 计”“全车型合计”“北京合计”“北京-合计”）的行一律不参与预警判级，等级固定为正常，避免汇总行重复触发预警。

## 规则流水线
页面数据统一经 src/alerts/pipeline.py 的 evaluate_frame 评估：完整规则引擎（含前置条件、组合规则、阈值矩阵），预警表显示“触发规则”“规则类型”两列。统计异常（IsolationForest、滚动 z-score）单独展示，不改变预警等级。
