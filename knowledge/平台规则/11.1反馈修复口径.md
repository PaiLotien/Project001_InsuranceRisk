# 11.1 反馈修复口径（2026-11-11）

对应文档：docs/feedback_20261101_resolution.md，分支 upgrade/v2。以下是修复后系统的计算口径，回答相关问题时以此为准。

## 合计行识别与剔除
函数 is_total_row（src/utils/helpers.py）检查“车型”“机构”“序号”三列，去掉全部空白后以“合计”“小计”“总计”结尾即视为合计行。能识别：合计、合 计、小计、总计、全车型合计、北京合计、北京-合计。
合计行的处理：不参与预警判级（等级固定为正常）；排行、明细、邮件、地图、归因均使用剔除合计行后的明细（detail_frame）；不计入 DQ001 求和。

## DQ001 保费占比合计校验
DQ001：主表非合计车型的保费占比合计应约等于 100%，容忍误差 ±1 个百分点（沿用原实现，非业务确认值）。
修复口径：校验前统一剔除各类合计行，再按“机构 + 来源 Sheet + 数据区块 + 期间”分组求和，只用主表。修复前“合 计”“小计”“全车型合计”等写法会被加进去，导致合计约 200%（翻倍）。
结果分三种：通过（|合计−100| ≤ 1）、不通过、无法执行（机构或占比缺失、格式无效或超出 0 至 100）。DQ002 为跨表总保费一致性（T2 当月累计签单保费与 T7 月签单保费），DQ003 默认不启用。

## 金额单位口径
平台标准字段：签单保费_万元（万元）、单均保费_元（元）、案均赔款_元（元）。上传解析（src/parser/table_blocks.py）会读取表头单位说明：
- 表头标明签单保费或满期保费单位为“元”时，除以 10000 换算为万元；
- 表头标明单均保费或案均赔款单位为“万元”时，乘以 10000 换算为元；
- 比例字段若是没有百分号的小数，系统保留原值并在侧栏提示“请确认是否需要乘100”，不擅自换算。
默认数据集（SUSEP 2011）的金额单位是巴西雷亚尔，字段名沿用“_万元 / _元”，页面已注明。

## 多表识别
上传工作簿时跳过合并标题行与空行，保留全部期间（含“当年”表与同比、环比数据），并显示各表块行数与排除原因。单位存在疑义时在侧栏提示。

## 无“机构”列样表与上传崩溃
上传后“核心指标表”“预警中心”崩溃的原因是把 DataFrame 存进 pandas 的 attrs，新版 pandas 不支持，已修复。没有“机构”列的样表默认机构为“全辖”。

## 其他修复项
- 一键导出：首页“一键导出”生成多 Sheet Excel 风控报告；“打印版”生成带打印样式的 HTML。
- 汉化：预警等级显示为红色 / 橙色 / 黄色，公式改为字母加中文解释。Streamlit 表格自带的 Sort 等菜单是框架内置，无法翻译。
- 首页城市风险地图：剔除合计行，按保费加权，颜色与黄 / 橙 / 红阈值对齐。
- 休眠规则：页面统一经 evaluate_frame 跑完整规则引擎。

## 仍需业务确认
- 橙色阈值 95% 为默认参考值；
- 红色是否从“严格大于 100%”改为“大于等于”；
- 第 6、7 项（DQ001、多表识别）基于合成填数样表验证，需用真实填写的工作簿复测；
- 邮件需在正式 SMTP 配置下做真实投递验收。
